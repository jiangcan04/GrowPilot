# 邮箱与手机号登录交接

更新：2026-10-27。本文为生产后端需求，当前网页只演示流程，不发送邮件或短信，不验证号码/邮箱所有权。

## 界面与账户行为

- 登录页切换“邮箱登录 / 手机号登录”，手机号先选择国家/地区区号，再输入本地号码。切换渠道重新开始挑战，旧倒计时不得串到新表单。
- 获取验证码后进入输入页，展示目标账号、有效期、重发倒计时及修改入口；新用户可填写昵称，老用户直接进入原工作区。
- 前端样例使用固定演示码123456、10分钟有效期和60秒重发间隔；生产环境移除演示码及“展示验证码”，真实发送成功才显示已发送。
- 账号菜单和个人资料显示当前登录身份；退出使服务端会话失效。手机号登录与邮箱登录都具备相同产品权限。
- 当前本机演示中邮箱与手机号分别创建账户，没有自动合并。生产按内部userId管理资料，可绑定多个已验证身份；不能凭昵称、客户端userId或未验证标识合并资料。

## 数据与接口

`users` 保存内部UUID。`auth_identities` 保存userId、type(email/phone)、normalizedValue、verifiedAt；(type, normalizedValue)全局唯一。号码使用E.164存储，服务端按地区校验；邮箱规范化策略需明确且一致，不能擅自去除邮箱本地部分的点或加号后缀。

`POST /api/v1/auth/challenges` 接收 `{channel:"email"|"sms",identifier,purpose:"login"}`，返回challengeId、expiresAt、resendAt。挑战绑定渠道、规范化目标、用途、发送状态、哈希验证码、过期和尝试次数。验证码不回传客户端，也不进日志。

`POST /api/v1/auth/sessions` 接收 `{challengeId,code,nickname?}`；不允许客户端替换挑战目标。服务端原子消费单次验证码、查找或创建已验证身份并建立安全Cookie会话。失败不消耗成功状态；并发请求只允许一次消费，避免重复建用户。过期、错误次数耗尽、重发失败各有清晰提示；重发成功后旧码失效。

未来若增加绑定/换绑界面，要求有效会话、近期重新验证及新身份所有权验证；已属于其他用户的身份返回冲突，禁止自动搬移资料或合并账户。此绑定界面不在本次前端新增范围。

## 供应商与防滥用

邮件与短信供应商由工程师提案，短信国家/地区覆盖、模板/签名和费用单独确认；当前区号选项不代表已开通短信服务。不支持的地区应明确提示，不能显示假发送成功。

按IP、设备/会话及目标身份组合限制发送频次、验证次数、并发和每日额度；前端倒计时不能代替服务端限流。返回一致的发送/登录提示以减少账户枚举。会话Cookie启用HttpOnly、Secure及合适SameSite策略，资源仍按当前会话userId鉴权。演示和生产环境隔离。

## 验收

1. 邮箱与手机号各自首次验证可建账户，再次验证进入原资料；退出后受保护接口返回401。
2. 区号切换、号码空格/连字符规范化及无效号码提示正确；超出供应商覆盖的地区不发送。
3. 错码、过期、超次数、重发冷却、服务商失败均显示真实状态，无万能码、明文码或假成功。
4. 同一挑战并发验证只消费一次；并发首次登录不生成重复身份。
5. A/B资料隔离；邮箱/手机号绑定冲突不得合并或泄漏资料；未验证标识不能获得账户权限。
