## 本轮功能

- 一键采集目标为 **BOSS 直聘岗位**，根据职位方向、城市、实习/全职、薪资、经验、学历和公司条件筛选，无须逐条粘贴链接；保留手动输入。当前只演示前端采集、筛选与收藏流程，展示虚构岗位，尚未接入 BOSS 直聘实时数据。正式接入需保留来源、岗位原文、发布时间（缺失则标未注明）与采集时间，并支持分页、去重和失败提示；不沿用“最新100条、每轮30条、六小时缓存”的旧来源限制。
- 采集区与岗位池共享“职位大类 → 细分岗位”两级分类；可组合地区、类型、薪资、工作经验、学历、公司行业、规模和融资阶段。手动岗位可补齐字段。未注明的信息不会推断为满足条件，海外年薪不混入人民币月薪或日薪筛选。
- 文件夹内用可流动的词云展示要求；大小参考提及岗位数，点击查看原文。可暂停、悬停暂停、键盘聚焦暂停，并遵从系统减少动画偏好。长标签缩略但保留完整标题与原文；要求过多分组浏览，完整列表仍保留。匹配只使用本轮勾选 JD，词云使用整个文件夹。
- 匹配页先选择方向再进入简历与匹配，不设置“合并要求”按钮。合并由分析内部执行，保留原文来源。
- “生成求职成长建议”先按缺口从已接入的公开案例源读取原文，再采用对应案例的实践做法形成建议。展示来源、短摘录、读取时间、背景限制与任务适用关系；课程页面只作补充资料。未读到适用案例时，显示等待经验依据，不能直接采纳，不提供没有支撑的成形学习计划。SQL / Python / Excel 不借用无关案例。旧建议草稿重新生成时升级，已采纳任务与成果保留。
- 经历库按教育、实习、项目、课程、科研、校园、技能与证书、其他经历分组；兼容旧分类。
- 最终成果通过“同步到经历库”进入“AI 识别或手动整理 → 修改预览 → 确认加入”。预览可修改名称、分类、时间、内容和链接；确认前不写入经历库，取消不新增。确认后保存本人修改与分类，并关联原成果防止重复。AI 原始内容先经过引用校验，人工修改另行标记。

## 在线服务

`worker/handler.mjs` 提供 `/api/status`、`/api/collect-jobs`、`/api/analyze`、`/api/recognize-outcome`、`/api/experience-sources`。在线服务由 Cloudflare Worker 运行。

真实 AI 需要在站点服务端设置 `OPENAI_API_KEY`，可选 `OPENAI_MODEL`。密钥不进入仓库或浏览器。未设置时页面明确显示“AI 尚未连接”，只有规则预览，成果不会假归档。

使用 OpenAI Responses API、严格 JSON 结构、`store:false`。请求需要同意发送材料，校验原始 JD / 个人材料引用。AI 未配置或返回无效内容时保留用户记录并报告错误。当前未使用真实密钥验证模型调用，接口通过隔离 mock 验证。

## 源码与本机运行

页面源文件在 `web/`，保留原有 PDF.js、JSZip 及授权。`npm run build` 通过 `scripts/build-worker.mjs` 将页面资产嵌入 Worker，输出 `dist/server/index.js` 和对应 hosting manifest。`dist/` 是生成内容。

Node 24+：

```sh
npm run dev
npm test
npm run build
node scripts/validate-artifact.mjs
```

无第三方 Node 依赖，无需安装包。`start.command` 启动 Node 本机服务；`start-ai.command` 使用 Python 的隐藏输入读取密钥并仅传入 Node 子进程环境，不写文件。Python `server.py` 保留旧版本机逐链接读取接口，仅用作兼容和独立测试，不是线上服务。

**采集来源更正（2026-10-27）：** 产品目标来源为 BOSS 直聘，不是 Remotive 或全球英文远程岗位。`worker/handler.mjs` 中旧的 Remotive 实验接口未被当前前端采集流程调用，不构成 BOSS 采集实现；正式开发须替换该旧适配，不能把旧源结果改名冒充 BOSS 岗位。当前页面不请求该接口。BOSS 接入范围、可用方式、分页数量和缓存策略需依据实际接入条件确认。

## 网上经验来源

`worker/experience-sources.mjs` 接入 Coursera Blog 的公开个人经历、Grow with Google 的转行故事、微软公开客户案例，按能力维度和具体技能选择读取，当前为 6 条已核对的候选文章。它不是全网搜索引擎，不宣称接入知乎、小红书、牛客或 BOSS 数据。

读取使用 HTTPS、固定可信来源和跳转检查、大小/超时限制与 12 小时成功缓存。正文只作为数据，不执行脚本。读取失败、限制访问或无法核对正文时分别报告，不将其当作成功来源。保存一个很短的原文摘录、来源 URL 和实际读取时间；经验摘要及练习转化由编辑整理并明确说明。培训平台与厂商刊载案例的宣传属性和个案局限在页面中标注。

主要参考：BOSS 直聘公开首页的职位层级 https://www.zhipin.com/ 。分类为面向 InternPilot 场景的简化组织，不代表 BOSS 官方接口或完整分类。相关页面和来源的核对记录见 docs/validation-20261026-cloud-cases.md。

## 完整案例示例与本条建议的资料

左侧“查看完整案例示例”加载一个明确虚构的小林案例：3 个岗位、1 份示例简历、4 条基础经历、预置示例匹配、3 项成长任务、1 份最终成果。每条建议中直接展示经验文章的示例关联与相应课程/教程。示例匹配和识别清楚标记为预置演示，不调用真实 AI。

示例使用独立的内存状态，进入时保留真实资料，退出时恢复；示例操作不会写入真实 localStorage、清除真实附件或调用线上采集。示例可以体验“取消预览不新增”“修改分类后确认加入”“经历复用于示例匹配”的闭环。

准备周期取消固定天数按钮，使用自定天数输入（1–730 天），截止日期、折合周数和投入预算联动。例：23 天、每天 2 小时，得到 46 小时预算。

经验来源模块已移除，案例按建议关联，支持更新/补充当前建议的案例。每条建议内另有“补充学习材料”，包括相关的 SQL、Python、Excel、UX、AI 评测、运营、项目管理或职场英语的官方课程/资料链接，并说明如何用于当前练习。可在编辑建议时添加自己的学习链接。课程支持学习，不单独充当经验依据。

### 当前交互精简（2026-10-27）

删除泛化的 AI 聊天侧栏及岗位、简历、经历、复盘的重复 AI 入口。主流程围绕三个结果：

1. 差距清单：每项要求并排展示已有经历、待补内容、下一步；直接补充材料或进入对应任务。

### 能力匹配到准备计划的分工（2026-10-27）

经历与对照页分别呈现已具备能力及其经历依据、岗位要求中待提升的能力。已有基础和进阶差距可以同时展示；信息不足的要求单独等待补充。右侧“AI 生成求职成长建议”可一次生成，也可逐项生成。界面统一采用“求职成长建议”名称。

生成只创建或复用 `suggested` 建议，跳转准备计划；不自动采纳，不跳转执行页。重复生成不重复创建，其他方向互不影响。准备计划负责查看、调整、加入或暂不加入本轮；确认加入后才成为执行任务。新用户不预先生成待选择建议。

准备计划统一显示当前方向的全部建议，包括历史保存、尚未加入、已加入和已完成记录，不再分区或折叠隐藏。点击“加入本轮计划”使用本轮时间预算安排任务，原卡片显示“已加入本轮计划 ✓”，进行中的任务可取消加入；取消不删除步骤、成果或建议。执行计划仅显示进行中的已加入任务。此流程仍为浏览器本地的前端示例。

每日执行前端：准备计划底部统一进入“安排执行计划”；执行页按本地规则演示岗位要求优先级、编号、每日时长切片、留出约 15% 余量、跨方向占用和未排入周期的提示。可手动调序、调整今日剩余分钟数、顺延未完成步骤；完成记录与成果保留。圆鼓鼓的小鸟“啾啾”可收起、减少动效，提供开始提示、拆小一步、学习材料与成果登记入口。提醒时间与通知样式仅作前端示例，没有接入模型、定时任务或系统推送。


GrowPilot 全页面伙伴：保留原有小鸟形象与颜色，名字改为“咕噜”；移除形象背板，仅在说话时展示气泡。五个页面共享一只小鸟，支持鼠标/触摸拖动、位置保存、窗口边界约束、键盘方向键移动、收起恢复、减少动效与默认位置。提醒来自真实的本地任务状态，可跨方向定位下一项今日任务，并提供页面下一步、困难拆解、材料与时间调整入口。每日首次访问仅提示一次，不在关闭网页后推送。内部数据键和接口名称保持兼容，原浏览器资料继续保留。

执行页以今日行动为首屏，每项交代所属计划、优先原因和本次产出，整体计划及排序说明放在下方。任务入口与咕噜共享同一个侧边助手，按计划和原步骤保存对话、拆解草稿及确认后的微步骤。拆解可以编辑、确认采用或放弃；小点进度不自动完成原步骤或计划，确认本次行动与登记成果保持独立。问答提供与任务有关的具体做法、例子和材料替代方案，未知自由问题明确说明尚未接入模型。当前为本地前端示例，不含真实 AI 调用或原生桌面悬浮能力。

执行界面简化：默认是紧凑的今日清单，每项只显示名称、所属计划、时长和“开始/继续”；已完成和全部计划默认收起。进入后在主内容中单独显示当前一步，移除常驻大侧栏与重复按钮。问咕噜统一承接做法、例子与继续拆解，按需展开，并默认仅显示最新回答；历史对话可展开。拆解先展示简短清单，点击修改才出现表单。完成小点后突出下一点，最后明确确认本次任务；成果登记集中在“更多”和完成后入口。原有进度、对话、文件、咕噜形象与拖动位置保留。

### 当前界面：四阶段导航与登录（2026-10-27）

主导航固定按操作顺序排列：**求职方向 → 成长计划 → 今日任务 → 我的积累**。求职方向含目标岗位与能力对照；我的积累含共享经历库、跨方向任务成果和信息复盘。能力结果不把缺少证据直接等同于不会；建议生成、加入本轮、每天执行、成果确认入库分别由对应页面承接。

新增独立登录页和侧栏底部账户菜单，提供前端邮箱验证码示例（123456）、新用户昵称、两个演示账户、个人设置、咕噜与提醒设置、账户切换、备份、当前账户重置与退出。原 v4/v3 浏览器记录首次迁入默认演示账户，并沿用原 IndexedDB 附件数据库；其他账户分别使用独立工作记录和附件数据库。退出保留记录，未保存表单才提示。所有身份状态均为本机前端演示，不发送邮件、不验证邮箱、不提供真实访问控制或云同步。

今日任务汇总全部方向并标注来源，可按方向筛选，统一每日时间预算并留出约 15% 余量。各方向周期、任务顺序和完成记录保留；排程异常整体回滚。咕噜与列表采用同一今日顺序，继续沿用原形象、拖动与位置偏好。当前验证见 `docs/validation-20261027-navigation-and-login.md`。
